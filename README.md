# Lidar Semantic Global Localization

Global localization for a differential-drive mobile robot (`bcr_bot`) from a **prior floor plan only — no SLAM pre-mapping**. The robot solves the "kidnapped robot" problem: starting from a uniform belief over the whole map, it recovers its pose using **semantic landmarks** (objects detected in the camera image) fused with a **LiDAR beam model**, inside a particle filter (Monte Carlo Localization).

This is a research re-implementation of:
- **Zimmerman et al.** — Semantic MCL: LiDAR beam model + a semantic *visibility* model that weights particles by how likely the detected objects are to be seen from each candidate pose given the floor plan. *(primary algorithmic reference)*
- **VLGLOC** — global localization from a floor plan using a VLM instead of a hand-crafted detector.

Detection uses either a **VLM (Gemini or a local Ollama model)** or **YOLOv8**, selectable at runtime.

> Status: simulation-first. Development runs `bcr_bot` in Gazebo Classic 11. Deployment target is a real corridor environment.

## 2. Detection model setup — where the models live

You pick **one** detection strategy. The MCL node listens on a different topic depending on which one you use (`semantic_model_type` parameter, see §6).

### Option A — VLM (default, `semantic_model_type: "vlm"`)

The streaming VLM detector (`vlm_streaming_node`) has two backends, chosen with the `vlm_backend` parameter:

- **`gemini`** (cloud): requires an API key. **No model file to place** — it calls the Google API.
  ```bash
  export GOOGLE_API_KEY="your_key_here"
  ```
  ⚠️ Requires internet. The deployment target is an offline edge device (its own WiFi hotspot), so Gemini will be unreachable there — this is a known open problem (see CLAUDE.md).

- **`ollama`** (local): runs a VLM on a local Ollama server (default `http://localhost:11434`). Pull a vision model first, e.g.:
  ```bash
  ollama pull llava
  ```
  No key needed; runs offline.

### Option B — YOLOv8 (`semantic_model_type: "yolo"`)

`yolo_detector.py` loads the weights with `YOLO('yolov8x.pt')` (a **relative** path), so the file is resolved against the **current working directory of the terminal that runs the node** — i.e. the workspace root. Place the weights there:

```
<workspace_root>/yolov8x.pt
```

If the file is absent, `ultralytics` auto-downloads it on first run (needs internet once). `*.pt` weights should **not** be committed to git (see §8).

## 3. Required map / world assets

These are runtime inputs, not generated by the code:

| Asset | Path | Purpose |
|-------|------|---------|
| Occupancy grid | `src/test_semantic_mcl/map/map.{pgm,yaml}` | The prior floor plan particles localize against. |

⚠️ **Portability constraint:** `map/map.yaml` and `semantic_mcl_params.yaml` currently contain **absolute paths** (`/mnt/ssd/lsgloc_ws/...`). After cloning, you must edit:
- `src/test_semantic_mcl/map/map.yaml` → `image:` to point at your `map.pgm`.
- `src/semantic_mcl/config/semantic_mcl_params.yaml` → `landmark_json_path:` to point at your `landmarks.json`.

## 5. Running the simulation — terminal by terminal

The integration launch file brings up the **world + robot + map server + MCL filter + landmark markers**, but **not** the detector or teleop — those are separate processes so you can swap detection strategy and drive the robot independently.

**Terminal 1 — simulator + filter stack**
```bash
source install/setup.bash
ros2 launch test_semantic_mcl test_semantic_mcl.launch.py
```
This starts: Gazebo (`level6_v2` world) → spawns `bcr_bot` → `nav2_map_server` (+ lifecycle manager) publishing `/map` → `semantic_mcl_node` (the particle filter) → `landmark_visualizer` (RViz markers on `/landmark_markers`).

**Terminal 2 — the detector** (pick the one matching `semantic_model_type`)
```bash
source install/setup.bash

# VLM (Gemini): export the key first
export GOOGLE_API_KEY="your_key_here"
ros2 run obj_detection vlm_streaming_node --ros-args \
  -p vlm_backend:=gemini \
  -p color_topic:=front_camera/image_raw \
  -p depth_topic:=front_camera/depth/image_raw \
  -p camera_info_topic:=front_camera/camera_info \
  -p camera_optical_frame:=front_camera_optical \
  -p landmark_json_path:=<abs_path>/landmarks.json
# (these params are also provided in src/test_semantic_mcl/config/bcr_bot.yaml)

# --- OR --- YOLO
ros2 run obj_detection yolo_node
```

**Terminal 3 — teleoperation** (drive the robot to accumulate observations)
```bash
source install/setup.bash
ros2 launch bcr_bot teleop.launch.py     # opens an xterm; use keyboard to drive /bcr_bot/cmd_vel
```

**Terminal 4 — RViz** (watch convergence)
```bash
source install/setup.bash
rviz2
```
Add displays for: `Map` (`/map`), `PoseArray` (`/particle_cloud` — the particle cloud), `Pose` (`/mcl_pose` — best estimate), `MarkerArray` (`/landmark_markers`). Watch the cloud start uniform and collapse toward the true pose as semantic + LiDAR updates accumulate.

> **Convergence model:** particles initialize uniformly over the whole free space. The beam model continuously gates particles against LiDAR; each VLM/YOLO detection multiplies in a semantic-visibility weight. Resampling fires only when effective sample size (ESS) drops below `particle_count / ess_threshold`.

## 6. Configurable parameters

### MCL filter — `src/semantic_mcl/config/semantic_mcl_params.yaml` (node `semantic_mcl_node`)

**Motion model** (odometry noise, Thrun's sample_motion_model_odometry):
| Param | Default | Meaning |
|-------|---------|---------|
| `alpha1`–`alpha4` | 0.2 | Rotational/translational noise coefficients (diff-drive). |
| `alpha5` | 0.2 | Only used by the omni model. |
| `motion_type` | `"differential"` | `"differential"` or `"omnidirectional"`. Set to match the real robot at deployment. |

**Beam model** (4-mixture LiDAR likelihood):
| Param | Default | Meaning |
|-------|---------|---------|
| `z_hit` | 0.5 | Weight of the Gaussian "correct hit" component. |
| `z_short` | 0.05 | Weight of the exponential "unexpected obstacle" component. |
| `z_max` | 0.05 | Weight of the max-range "no return" spike. |
| `z_rand` | 0.5 | Weight of the uniform random-measurement component. |
| `sigma_hit` | 0.5 | Std-dev of the hit Gaussian. Larger = softer, less unimodal. |
| `lambda_short` | 0.1 | Rate of the short-reading exponential. |
| `z_max_val` | 12.0 | LiDAR max range (m). |

**Particle filter:**
| Param | Default | Meaning |
|-------|---------|---------|
| `particle_count` | 7500 | Number of particles. Higher = better global coverage, more cost. |
| `ess_threshold` | 2.5 | Resample when `ESS < particle_count / ess_threshold`. |
| `w_slow`, `w_fast` | 0.0 | Augmented-MCL running averages of measurement likelihood (random-particle injection). |
| `alpha_slow`, `alpha_fast` | 0.001, 0.1 | Decay rates for the slow/fast averages. |

**Semantic model:**
| Param | Default | Meaning |
|-------|---------|---------|
| `semantic_model_type` | `"vlm"` | `"vlm"` → subscribes `vlm/semantic_detections`; `"yolo"` → `yolo/semantic_detections`. |
| `landmark_json_path` | *(abs path)* | Path to the landmark database. **Edit after clone.** |
| `sigma_bearing` | 0.3 | Std-dev (rad) of the bearing likelihood. |
| `sigma_range` | 1.0 | Std-dev (m) of the range likelihood (only used if `use_range`). |
| `use_range` | `false` | Zimmerman uses bearing only; set `true` to also gate on range. |
| `semantic_min_confidence` | 0.6 | Detections below this confidence are dropped (limits VLM hallucination impact). |

### Detector — `src/test_semantic_mcl/config/bcr_bot.yaml` and CLI

| Param | Meaning |
|-------|---------|
| `color_topic`, `depth_topic`, `camera_info_topic` | Input image topics (synced via `message_filters`). |
| `camera_optical_frame` | Frame the detection is computed in, before TF to `base_link`. |
| `fx, fy, cx, cy` | Camera intrinsics (else taken from `CameraInfo`). |
| `throttle_hz` | VLM call rate cap (cloud cost / latency control). |
| `vlm_backend` | `gemini` or `ollama`. |
| `landmark_json_path` | Constrains the VLM's output vocabulary to known labels. |

### Packages

| Package | Lang | Role |
|---------|------|------|
| `bcr_bot` | — | Robot URDF/Xacro + Gazebo launch files (5 simulator variants). |
| `semantic_msgs` | IDL | `SemanticDetection{label, bearing, range, confidence}` and `SemanticDetectionArray`. The detector↔filter interface. |
| `obj_detection` | Python | Detection nodes: `vlm_streaming_node`, `vlm_service_node`, `yolo_node`. Converts 2D detections to bearing/range and transforms to `base_link`. |
| `semantic_mcl` | C++ | The particle filter and its motion/beam/semantic models. Executable `semantic_mcl_node_exec`. |
| `test_semantic_mcl` | Python | Integration: launch file, map, `landmarks.json`, worlds, `landmark_visualizer`. |

### Key topics

| Topic | Type | Direction |
|-------|------|-----------|
| `/scan` | `sensor_msgs/LaserScan` | → filter (beam model; every 20th beam used) |
| `/odom` | `nav_msgs/Odometry` | → filter (predict step) |
| `/map` | `nav_msgs/OccupancyGrid` | → filter (transient-local; one-shot init) |
| `vlm/semantic_detections` or `yolo/semantic_detections` | `semantic_msgs/SemanticDetectionArray` | → filter (semantic update) |
| `/mcl_pose` | `geometry_msgs/PoseWithCovarianceStamped` | filter → RViz (best estimate) |
| `/particle_cloud` | `geometry_msgs/PoseArray` | filter → RViz (the belief) |
| `/landmark_markers` | `visualization_msgs/MarkerArray` | visualizer → RViz |
